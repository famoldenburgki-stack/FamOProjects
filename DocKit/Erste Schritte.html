DocKitby Tim Oldenburg

Erste Schritte

Vorlagen und Textbausteine in jedes Programm einfügen — per Tastendruck. Nichts zu installieren, nichts einzurichten.

Loslegen

  1. 1
    Ordner auf den Stick kopieren. Vollständig, mit allen Unterordnern.
  2. 2
    Doppelklick auf DocKit.exe. Unten rechts in der Taskleiste erscheint ein blauer Kreis mit DK — eventuell hinter dem kleinen Pfeil versteckt.
  3. 3
    Beim ersten Start wirst du gefragt, wo deine Bausteine liegen sollen: eine vorhandene Datei öffnen oder eine neue anlegen. Eine neue startet mit vier Beispielen zum Ausprobieren.
  4. 4
    Irgendwo Strg + Alt + T drücken — in Word, in Outlook, im Fachverfahren. Die Auswahl geht auf, du wählst, der Text steht da.

Beenden: Rechtsklick auf das Symbol unten rechts → DocKit beenden.

„Der Computer wurde durch Windows geschützt"

Beim ersten Start kann Windows eine blaue Meldung zeigen: Unbekannter Herausgeber. Das ist kein Fehler und kein Virenfund. Windows sagt damit nur: Diese Datei trägt keine gekaufte Herstellersignatur, und sie kam über das Netz auf diesen Rechner.

So geht es weiter: In der Meldung auf Weitere Informationen klicken, dann auf Trotzdem ausführen. Das war es — beim nächsten Mal kommt die Meldung nicht wieder.

Damit die Meldung gar nicht erst erscheint: Doppelklick auf Windows-Warnung aufheben.bat neben der Programmdatei. Das entfernt die Herkunftsmarkierung, die Windows an heruntergeladene Dateien hängt. Es braucht keine Administratorrechte und ändert nichts am Rechner — nur die Markierung an diesen Dateien.

Noch einfacher, wenn du die ZIP-Datei gerade erst heruntergeladen hast: Rechtsklick auf die ZIP-Datei → Eigenschaften → unten Zulassen ankreuzen → OK, und erst danach entpacken. Dann ist keine der entpackten Dateien markiert.

Wer die Warnung ganz vermeiden will, bräuchte ein Signaturzertifikat einer anerkannten Stelle — das kostet Geld und muss jährlich erneuert werden. In den Dateieigenschaften unter Details steht als Hersteller trotzdem Tim Oldenburg; diese Angabe wird von Windows nur nicht geprüft.

Wenn die Programmdatei nicht startet

Manche Arbeitsplätze lassen unsignierte Programme nicht zu. Dann führt der zweite Weg zum Ziel: Doppelklick auf Falls die Programmdatei blockiert ist.bat. Das startet dasselbe Programm, nur über Windows-Bordmittel statt über die .exe.

Zeigt auch das nichts, hilft Hilfe bei Problemen.bat — dort bleibt ein schwarzes Fenster mit der Fehlermeldung stehen.

Fester TextGrußformel Wird sofort eingefügt, ohne Nachfrage.

Für den Test besonders interessant

Dieser Ordner ist bewusst leer ausgeliefert: Es liegt keine Bausteindatei bei. Damit lässt sich genau das prüfen, was im Alltag einmal passiert — der allererste Start.

Zu prüfenErwartetes Verhalten
Erster Start überhaupt Willkommensfenster mit zwei Möglichkeiten: vorhandene Datei öffnen oder neue anlegen.
Neue Datei anlegen Speichern-Dialog, danach vier Beispielbausteine. Die Datei trägt die Endung .tbd.
Zweiter Start Keine Frage mehr — die zuletzt benutzte Datei wird geöffnet.
Zweite Datei anlegen Rechtsklick aufs Symbol → Textbausteindatei → Neue Datei anlegen. Danach unten links in der Übersicht zwischen beiden wechseln.
Auf einem anderen Rechner Stick anstecken, starten — die eigenen Einstellungen sind da, weil sie mitgereist sind.

Gut zu wissen: Eine Bausteindatei ist eine ganz normale Datei. Sie darf auf einem gemeinsamen Laufwerk liegen, damit eine Dienststelle dieselben Vorlagen benutzt — und daneben führt jeder seine eigene.

Was das Programm nicht tut

Keine Netzverbindung, kein Eintrag in die Registry, kein Autostart, keine erhöhten Rechte, kein Tastaturmitschnitt. Es läuft nur, solange du es geöffnet hast. Einzelheiten samt Fundstellen im Quelltext stehen in PRUEFUNG.md.
